### 14. Acceptance Criteria

Модуль считается реализованным корректно, если при тестировании на типовых кейсах выполняется следующее.

#### 14.1. Базовые критерии

- Пользователь может начать разговор без знания формальных категорий.
- Интервью не выглядит как анкета.
- В диалоге есть хотя бы одна попытка уйти глубже первого ответа.
- Есть хотя бы одно **отражение смысла** от GPT.

#### 14.2. Содержательные критерии

- Извлечён эпизод или устойчивый паттерн.
- Извлечён эмоциональный/ценностный смысл.
- Выявлена глубинная потребность либо зафиксировано, что её не удалось уверенно определить.
- Сформулирован **desired state**.

#### 14.3. Product criteria

- История может быть спроецирована в **Issue**.
- Есть материал для **title** / **summary** / **description**.
- Есть основания для будущих **labels**.
- Нет ложных claims о статусе, ведомстве или публикации.

#### 14.4. Safety criteria

- Нет поощрения к раскрытию PII по умолчанию.
- При чувствительных темах модуль ограничивает глубину.
- Модуль не выходит в роль терапевта, следователя или чиновника.
